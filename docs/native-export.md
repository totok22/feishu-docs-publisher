# 原生 Callout 与 PDF 导出

本功能整合自 [HeShiLie/feishu-docs-publisher](https://github.com/HeShiLie/feishu-docs-publisher) 的四个提交：`6a8c0fa`、`25d9786`、`1ab8543` 和 `9f8bd4c`。本项目保留原有插件名称、版本历史、frontmatter 选项、忽略规则和媒体恢复功能。

## 启用与迁移

在“设置 → 内容”打开“原生 Callout 折叠”。默认关闭，保存后同步、手动同步、目录同步和 Git hook 使用同一设置。含 Callout 的笔记会走原生导出，普通笔记继续使用原有 Markdown 同步。

已有文档首次转换会重建正文，保留文档 URL。块 ID 会改变，段落评论和块定位链接可能失效；只存在于飞书的修改也可能丢失。先把远端修改合并回本地，再使用自动策略同步。安全增量策略会阻止已有文档的首次转换，新建空文档不受此限制。

关闭开关只影响尚未转换的文档。已转换文档继续使用原生同步，包括删除全部 Callout 后的后续同步，以免静默切回另一套块结构。

需要在 `lark-cli` 中授予 `docx:document.block:convert` 权限。缺少权限时，按 CLI 提示补充授权。

## Callout 结构与同步

Callout 标题成为文本父块，正文、嵌套 Callout、列表、代码和本地媒体保留在对应子块内。`-` 初始折叠，`+` 初始展开，无符号时也初始展开。标题行按类型设置背景色，不复刻 Obsidian 的完整背景和边框。

同步按顶层子树比较，保留相同的前缀和后缀，替换中间变化范围。修改深层内容会重建所属顶层 Callout；如果两处修改相隔较远，中间未变的子树也可能重建。被重建范围的块 ID 和评论位置不保证保留。

读者的展开和收起不视为正文冲突。正文变化时，尽量保留同名父块的读者折叠状态。检测到飞书正文修改会停止，即使使用覆盖入口，也需要先合并远端内容。

原生映射、待完成事务和已上传图片 token 保存在插件 `data.json` 的 `nativeCalloutStates` 中。替换前保存计划，创建使用幂等键；媒体完成并验证后才删除旧范围。图片直接绑定在原生图片块上，视频复用原有文件预览和持久上传记录。失败后保留事务，下次同步继续恢复。

## PDF 引用与截图

普通 PDF 引用保留别名、文件名和页码文字。已发布或已绑定的 PDF 转为飞书原生文件引用；未绑定时显示可读说明。选区参数不会转为精确导航。

```md
[[paper.pdf#page=3|参考论文]]
![[paper.pdf#page=3|600]]
![[paper.pdf#page=3&rect=10,20,110,70|300]]
```

第二行导出整页图片，第三行导出 PDF++ 指定区域。图片保留尺寸和页码图注，并缓存到系统临时目录，源 Markdown 和 PDF 保持原样。普通文件引用需要先发布或绑定 PDF，页面和区域图片可以直接从本地 PDF 渲染。

Obsidian 使用内置 PDF.js，附件索引来自 Vault 文件列表。Git hook 使用 Poppler，需要 `pdfinfo` 和 `pdftoppm`，旋转页面需在 Obsidian 内发布。PDF 文件本身仍只通过手动同步或目录同步更新，截图会在所属笔记下次同步时重新检查；只修改 PDF 不会触发笔记自动同步。

## 科研标签配色

“科研标签配色”默认关闭，仅作用于原生导出。开启后，冒号前的显式加粗标签使用红字、黄色背景，保留加粗。普通粗体、冒号和代码保持原样。切换后，下次同步会重新检查样式，即使 Markdown 没有变化。

```md
**结论**：结果稳定。
```

## 限制与验证

- 原生路径拒绝网络图片，请先保存到库内。普通 Markdown 路径仍由原有导入处理网络图片。
- 单次变化范围超过 1,000 块时，在写入前停止。
- `- > [!note]` 这种列表标记与引用同处一行的布局尚未支持，会提示错误。
- Mermaid、复杂表格、脚注和 HTML 依赖飞书转换器，不保证完整还原。
- 自动化测试覆盖嵌套结构、不变跳过、子树替换、远端冲突、图片和视频混合、上传中断恢复、旧绑定别名、开关关闭后的原生状态保留，以及精确模式的迁移保护。
- 本次整合没有重新执行真实飞书页面的折叠交互验收。原 fork 的 API 验证记录属于原作者测试，不等于本次整合的实际页面验收。
